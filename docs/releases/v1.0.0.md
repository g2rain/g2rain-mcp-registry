# g2rain-mcp-registry v1.0.0

## 定位与交付

`g2rain-mcp-registry` 是 G2rain 开源智能体平台中的 MCP 工具目录、协议适配和下游调用代理服务。它管理外部服务和工具资料，解析工具输入 schema，并在 `/mcp` 向 Agent Runtime 提供 `tools/list` 与 `tools/call`。它不交付整个平台能力，也不替代 Agent Studio 的 Agent/Skill 配置、Agent Runtime 的任务执行、Model Nexus 的模型接入、网关鉴权或部署编排。

G2rain 平台由 SaaS 基座、知识库、智能体、业务应用、前后端工具链和部署编排共同组成。当前平台公开说明为：基础搭建、现有 SaaS 基座和知识库已可用；智能体平台与智能客服已开发完成并开源；交易、计量计费等商业化能力仍处于规划设计中。

## 构建和运行要求

- 项目版本事实源：根 `pom.xml` 的 `<revision>1.0.0</revision>`；所有模块继承该版本。
- Java：25（`maven.compiler.release=25`）；构建命令为 `mvn clean verify`。
- 关键框架：Spring Boot 4.1.2、Spring Cloud 2025.1.4、Spring AI 2.0.2、Jib Maven Plugin 3.5.2。
- 运行依赖：MySQL、Redis、Nacos 和下游 MCP/HTTP 服务；主类为 `com.g2rain.mcp.registry.Application`，`SERVER_PORT` 默认 `8080`，默认 profile 为 `nacos`。

## 镜像和发布顺序

镜像为 `ghcr.io/g2rain/g2rain-mcp-registry`，基于 `eclipse-temurin:25.0.4.1_1-jre`。在发布变更、工作流和本文件先进入 `main` 后，创建并推送 `v1.0.0` tag。工作流仅接受 `vX.Y.Z` tag，验证 tag 提交已进入 `origin/main`、本文件非空且 POM 版本匹配，随后运行 `mvn clean verify` 并推送：

- `ghcr.io/g2rain/g2rain-mcp-registry:1.0.0`
- `ghcr.io/g2rain/g2rain-mcp-registry:sha-<完整提交 SHA>`

不推送 `latest`，不创建 GitHub Release，也不部署服务。OCI 标签包含 source、url、title、version 和 `Apache-2.0`（与仓库 LICENSE 一致）。

镜像 job 成功后调用 API Maven 工作流，向 `https://maven.pkg.github.com/g2rain/g2rain-mcp-registry` 上传 `com.g2rain:g2rain-mcp-registry:1.0.0` 父 POM 和 `com.g2rain:g2rain-mcp-registry-api:1.0.0`。Maven 工作流也可手动运行，但所选提交必须在 `main` 历史中；重复上传同一版本可能冲突，不覆盖既有制品。镜像和 Maven 发布不是事务性操作，后者失败不会回滚前者。消费方须配置 Maven repository 与认证；跨仓库 `GITHUB_TOKEN` 读取需要授予包访问权限，个人读取使用安全注入的 `read:packages` PAT classic。公开 GHCR 镜像的匿名拉取不代表 Maven 匿名可解析。

## 镜像内容与配置风险

Jib 将 Spring Boot 的依赖、应用类和 `src/main/resources` 资源放入最终镜像，并以该主类启动；端口声明为 8080。已跟踪的 `application-nacos.yml` 和 `application-dev.yml` 会随资源进入镜像，当前含 Nacos/MySQL 默认凭据及本机地址。这些值不应当作为生产密钥：用容器环境变量、Nacos Secret/配置管理或编排平台 Secret 挂载注入生产凭据。本次没有删除这些文件、变更凭据或改写 Git 历史，维护者必须在实际发布前处置风险。

首次成功推送后，在 GitHub Packages 的 **Package settings → Change visibility → Public** 设为公开；若组织策略禁止修改，请联系管理员。已有包出现 `denied` 时，先核对 **Package settings → Actions access** 是否为本仓库授予写权限和组织 Packages 策略，不能仅凭 `packages: write` 判断权限足够。

## 已知限制与验证状态

- 此工作流的 CI 验证为 Maven `clean verify` 与 Jib 推送；不验证 Nacos/MySQL/Redis/下游 MCP 的连通性、Gateway 路由、`/mcp` 协议交互、匿名拉取、在线演示或实际部署。
- 本地容器脚本使用 `jib:dockerBuild` 并跳过测试；须先单独运行 `mvn clean verify`。
- 本说明随首次发布准备而新增；截至此变更尚未创建 tag、执行 GHCR 推送、修改包可见性或部署服务。
